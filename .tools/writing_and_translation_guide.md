## 0. Non-negotiable — 자연스러운 한국어 + 전문 번역가 검수

**원칙**: 모든 페이지는 (1) 자연스러운 한국어로 번역·다듬어진 후 (2) 전문 번역가의 검수를 거쳐 배포한다. 어느 한 단계도 생략 없음.

**왜**:
- AI/MT 직역 + 영어 어순 잔재(passive, "~을 통해", "~에 의해")가 환자 신뢰를 깎는다.
- 의학 용어는 한국 임상 표준 표기가 따로 있다 (예: KLCA·KASL·식약처 명명).
- 1저자 voice는 표면 문장만 바꿔서는 살지 않는다 — 어순·호흡·조사 단위까지 한국어 화자의 직관이 필요.

### 워크플로우 (필수 3단계)

| 단계 | 담당 | 산출물 위치 |
|---|---|---|
| 1. 한국어 초안 작성 — 본 가이드 7기법 적용 | Claude / Codex / 저자 | `draft/` (또는 PR open) |
| 2. 자연스러운 한국어 번역·정리 (직역 잔재 제거, 어순·호흡 복원, 용어 통일) | 동일 작업자 또는 별도 정리 패스 | `for_review/` |
| 3. 전문 번역가 검수 — **배포 전 필수** | 외부/내부 번역가 | merge 후 published |

**게이트**: 3단계 검수 통과 전에는 site에 published 상태로 올라가지 않는다. main에 merge하기 전에 번역가 sign-off 필수.

### 검수 체크리스트 (번역가에게 전달)

- [ ] 영어 어순/passive 잔재 없음 — "~에 의해 X됩니다" → "X입니다"
- [ ] 번역체 표현 다듬음 — "~을 통해", "~에 있어서", "~함에 따라", "~로 인하여" 최소화
- [ ] 의학 용어 한국 표준 표기 (KLCA·KASL·식약처 명명 우선)
- [ ] 약물명: 영문 통용명 우선, 첫 등장 시 한글 음역 병기 — `atezolizumab(아테졸리주맙)`
- [ ] 환자 호칭 일관성 — "환자분"으로 통일 (페이지 내 "환자분"·"환자" 혼용 금지)
- [ ] 단정·헤지 비율이 1저자 voice에 부합 (헤지 과다 금지)
- [ ] 짧은 단문과 긴 설명문의 호흡 변화
- [ ] FAQ 답변에서 환자가 바로 이해할 수 있는 어휘 사용 (전문 약어는 풀어 쓰기)

### 적용 범위 — 예외 없음

- 사례 / CC / Updates / 세부주제 / hub TLDR / 자동 주입 JSON-LD title·description / breadcrumb / OG meta — **모두 동일 게이트**
- page-photo caption, alt text도 본문 변경 시 함께 검수
- SVG 인포그래픽 내 텍스트도 검수 대상 (한국어 어휘·호칭 통일)

## 1. AI 글의 7가지 tell — 회피 목록

| Tell | 회피법 |
|---|---|
| 모든 문단 길이 비슷 (sentence rhythm 단조) | 짧은 단정 + 긴 설명 mix. "그렇습니다." 같은 한 문장 단락 OK |
| 헤지 과다 ("일반적으로", "대체로", "고려할 수 있습니다") | 단호하게: "X입니다", "이건 안 됩니다", "저는 Y가 더 낫다고 봅니다" |
| 빈 연결어 ("이를 통해", "이러한 점에서", "더 나아가") | 그냥 빼거나 구체적 인과로 대체 |
| 모든 것을 N단계/N축으로 구조화 | 산문으로 풀어 쓰기, 굳이 번호 매기지 말기 |
| 1저자 화법 부재 | "저는", "제 외래에서는", "제 환자분 중에" 자주 쓰기 |
| 임상 일화 부재 | "지난주 외래에서 ~한 환자분", "전공의 시기에 자주 봤던" 같은 후크 |
| 항상 균형 잡힌 양면 framing | 한쪽으로 단호하게 입장 — "교과서는 X라지만 저는 Y" |
| 메타 문장 ("이 부분이 중요합니다") | 그냥 본문에 녹여 |
| 지역 맥락 부재 | "한국 보험은", "KLCA-NCC는", "서울대병원에서는" |

## 2. 인간미 회복 7가지 기법

### 1. Author opener (Update 페이지 도입부)
"제가 전공의·전임의 시기에 ~ 했습니다. ~ 시험이 그 관성을 깬 시험입니다."
"외래에서 자주 받는 질문이 있습니다 — '~?' 이 페이지는 그 질문에 대한 답입니다."

### 2. 단호한 임상 의견 (SUBGROUP/CRITIQUE)
"교과서는 X로 권고합니다. 다만 저는 진료 현장에서 Y에 더 비중을 둡니다."
"이 결과는 모든 환자에 적용되지 않습니다. 제가 회피하는 케이스는…"

### 3. 임상 일화 (간단히, overdone X)
"지난주 외래에서 ~한 환자분이 있었습니다."
사례 페이지(/케이스/)와는 다른 질감 — 더 짧고 부수적.

### 4. 한국 임상 맥락 (모든 글에)
"KLCA-NCC 2022는 X로 권고합니다. 다만 한국 보험은 Y이고…"
"한국 real-world data에서는 시험보다 약 2-3개월 짧은 OS…"
"서울대병원에서는 다학제 회의에서 ~를 표준으로 봅니다."

### 5. 한계·불확실성 직설
"이 결과는 ~까지만 답합니다."
"솔직히 말씀드리면 이 부분은 학회에서도 논쟁적입니다."
"제 답은 '아직 모릅니다'입니다."

### 6. 환자 시점 통합 (CC 페이지)
"환자분들이 자주 오해하시는 것은 ~ 입니다. 사실은…"
"이 말을 듣고 외래에 오시는 분이 많습니다."

### 7. 짧은 단정 — 호흡 변화
긴 설명 단락 사이에 한 문장 단락을 넣어 호흡을 바꾼다.
예: "그래서 저는 이 시험을 분기점이라고 봅니다."
예: "정답은 없습니다."

## 3. 페이지 톤 가이드

### Update 페이지 권장 구조 (deep + human)
```
한 문단 요약 (tldr) — 1저자 시점 + 핵심 결과 한 문단
BACKGROUND — 왜 이 시험이 의미 있나, 이전 시도 왜 실패했나, 메커니즘
METHODS — 핵심 설계 + design choice의 미묘한 의미 + 일반화 한계 단서
FINDINGS — 표·그래프 + 핵심 수치
SUBGROUP — 균열 + 저자 의견
LIMITATIONS — 한계 솔직하게
한국 임상 — "저는 외래에서 이렇게 결정합니다" 1-5단계 ol
BOTTOM LINE — 단호하게 한 문단
References
```

### 세부주제 페이지 권장 톤
- 본문 문단 시작에 종종 1저자 의견: "제 외래에서 자주 받는 질문은…"
- 굳이 번호 매기지 않고 산문으로 풀기
- 한국 적용 코너 — "KLCA-NCC는 BCLC를 그대로 쓰지 않고 X 옵션을 더 넓게 둡니다"
- FAQ는 "환자분이 자주 묻는…" 톤

### 사례 페이지 톤 (이미 정착됨)
- 격식체 입니다/했습니다 유지
- intro에 환자 한 단락 prose
- 익명화 disclaimer 페이지 끝에만
